# 基础数据审核工具（统信 UOS / Linux 原生版）使用与分发指南

适用目录：本 `uos/` 树。这是唯一维护源码的树（`uos_audit/` 已是空壳）。

---

## 一、目录结构

```
uos/
├── run.py                        # 程序入口（Flet 桌面工作台）
├── main.py                       # 兼容入口
├── src/uos_audit/                # 核心代码（审核/计算/条件格式/流程等）
├── tests/                        # pytest 测试
├── data/                         # 用户设置/流程配置/模板索引（业务文件，分发时目标机自备）
├── .venv/                        # Python 3.12 虚拟环境（含 flet/openpyxl，本机已建好）
│
├── 启动-无终端.sh                 # 双击/桌面启动（无终端，供 .desktop 用）
├── 启动Flet-UOS.sh               # 终端启动
├── 安装依赖Flet-UOS.sh           # 首次建 .venv + 装依赖
├── 打包deb.sh                    # 打 deb 安装包（推荐分发方式）
├── 打包Flet-UOS.sh               # flet build 产出发行目录（deb 的前置）
├── 收集依赖.sh                   # 内网离线依赖收集
│
├── deb/                          # 分发产物目录
│   ├── base-audit-uos_*.deb      # 主安装包（含 Flutter 自包含运行时）
│   ├── deps/                     # 离线依赖 .deb（225+ 个，含 LibreOffice）
│   ├── 内网安装说明.txt           # 给目标机的安装步骤
│   ├── 依赖清单.txt               # 依赖清单
│   └── 下载依赖.py               # 批量下载依赖的开发工具（可不随分发）
├── docs/                         # 文档（本文件）
├── requirements*.txt  pyproject.toml
└── .gitignore
```

> **脚本为什么留在根目录**：启动/打包/收集脚本都用
> `ROOT_DIR="$(cd "$(dirname "$0")" && pwd)"` 假设"脚本所在目录=项目根"来定位
> `.venv`、`src`、`deb`。移到子目录会失效，故留在根目录。

## 二、本机开发 / 运行

### 首次（建环境）

```bash
./安装依赖Flet-UOS.sh     # 建 .venv + pip 装 flet/openpyxl
```

> 注意：本机系统 python3 缺 ensurepip（python3.12-venv 未装），直接 `python3 -m venv`
> 会失败。若需重建环境，用"克隆现成 .venv"或先装 python3.12-venv。

### 运行

```bash
./启动Flet-UOS.sh            # = .venv/bin/python run.py --flet
# 或双击桌面「基础数据审核工具（统信版）」图标（指向 启动-无终端.sh）
```

### 引擎自检 / 冒烟

```bash
.venv/bin/python run.py --check-engine
PYTHONPATH=src .venv/bin/python -m pytest tests/ -q   # 全量测试
```

> 依赖 LibreOffice 做公式重算。本机是 `/opt/libreoffice26.8` 独立包，
> 程序能自动找到（`--check-engine` 会显示）。

## 三、打包分发（关键）

deb 是最推荐的分发方式：装完带开始菜单图标、自包含 Flutter 运行时，
**目标机不需要装 Python / 建 venv**。

### 步骤

```bash
./打包deb.sh --build          # 一步：flet build + 打 deb → deb/base-audit-uos_*.deb
# 或分开：
./打包Flet-UOS.sh             # 1) flet build linux → 发行目录
./打包deb.sh                  # 2) 把发行目录组装成 deb
```

打包完脚本末尾会**打印依赖提示**（Depends 需要哪些系统包）。

### 分发前必读：目标机版本与依赖

| 目标机 | LibreOffice 形态 | 能否直接装 deb | 说明 |
|---|---|---|---|
| UOS V25（标准源） | deepin 源 libreoffice-calc | ✅ | deb 的 Depends 会自动拉 LO |
| UOS V20（标准源） | deepin 源 libreoffice-calc | ✅（需 V20 版依赖，见下） | 不能混用 V25 收集的依赖 |
| 装了 /opt 独立 LO | /opt 独立包 | ⚠️ | dpkg 无 libreoffice-calc 会装失败 |

> deb 内是 **flet build 的自包含产物**（libpython + site-packages + Flutter 运行时），
> 链着**构建机**的 glibc/GTK。**必须在本机（或与目标机同版本同架构的 UOS）上打包**，
> 不能跨版本/跨架构。V25 打的包直接装 V20 可能因 glibc 过新启动失败。

## 四、内网机器（离线）部署

目标机不能联网时，需要把**全部依赖 .deb** 一起带过去。

### 1) 在有网的机器上收集依赖

收集脚本用**当前系统软件源**解析依赖，所以：

- 目标机是 **V25** → 在 V25 机器上跑本 `uos/` 里的 `./收集依赖.sh`
- 目标机是 **V20** → 必须在能连 **V20 源**的机器上跑（在 V20 上放一份 `uos/` 或用共享文件夹），
  会生成 V20 版 `deb/deps/`

```bash
./收集依赖.sh                 # 收集 deb/ 下最新 deb 的依赖 → deb/deps/
# 或指定 deb： ./收集依赖.sh deb/base-audit-uos_1.1.0_amd64.deb
```

产物：`deb/deps/` = 全部直接+传递依赖 .deb（含 LibreOffice）+ 主 deb + 依赖清单.txt。

### 2) 拷贝到内网机

把整个 `deb/` 目录拷过去（U 盘/共享文件夹）。约 180MB。

### 3) 内网机安装

```bash
cd deb/deps
sudo dpkg -i *.deb            # 装依赖 + 主程序；缺顺序再执行一次
sudo dpkg -i *.deb
/usr/bin/base-audit-uos       # 启动；或开始菜单「基础数据审核工具（统信版）」
```

装完文件位置：
- 可执行程序：`/opt/base-audit-uos/基础数据审核工具-统信`
- 命令行启动：`/usr/bin/base-audit-uos`
- 开始菜单图标：`usr/share/applications/base-audit-uos.desktop`

## 五、虚拟机 / 无 GPU 环境说明

deb 的启动器会自动检测虚拟显卡（VMware/QXL/VirtIO 等 vendor id）并切**软件渲染**
（`LIBGL_ALWAYS_SOFTWARE=1`），避免 Flutter 硬件 GL 在无 GPU 环境段错误。

若仍异常可强制：

```bash
BASE_AUDIT_FORCE_SOFTWARE=1 /usr/bin/base-audit-uos
```

## 六、其它说明

- **条件格式提取**：纯 openpyxl 实现（不依赖 LibreOffice UNO，LO 读不到渲染色）。
  支持 cellIs 与公式型(expression)规则。详见 docs/变更记录-20260902晚.txt。
- **业务文件不随程序分发**：模板、历史审核说明.xlsx、data/ 为程序外文件，
  目标机首次运行会让你选择目录。
- **版本**：当前 1.1.0。改版本号：`VERSION=1.2.0 ./打包deb.sh`。
